AI Agent · 全栈项目

电商智能客服系统 Agent-commerce

独立的电商智能客服平台：以 LangChain Agent 为统一 AI 入口，实现智能问答、订单查询与 RAG 知识库检索；前后端分离，Docker 一键起基础设施，含完整鉴权与防枚举安全设计。

🛠 技术栈

后端 Python 3.11 · FastAPI 前端 Vue3 · TypeScript · Vite · Pinia 数据库 PostgreSQL 15 缓存 Redis 7 AI LangChain Agent · 通义千问 / DeepSeek RAG Chroma 向量检索 通信 WebSocket 实时聊天 运维 Docker Compose · Alembic 迁移

🏗 系统架构

✨ 核心功能

🤖 LangChain Agent 智能问答

AI 入口统一收敛为 LangChain Agent，订单查询、FAQ 检索、转人工提示均通过 Tool Calling 完成，旧直连 LLM 调用仅保留兼容封装。

📋 订单查询

游客无需登录即可查单，但需「订单号 + 下单手机号」双要素验证——订单号连号可猜，双要素从设计上封死枚举攻击面。

📚 RAG 知识库

LangChain + Chroma 向量检索本地女装 FAQ；高频问题从历史消息聚合，运营沉淀的标准答案优先于基础检索返回。

💬 WebSocket 实时聊天

全双工实时会话；WebSocket 无法带请求头，token 走查询参数并校验会话归属，浏览器 API 限制下的务实鉴权方案。

🛡 运营后台

/api/faq/* 走 X-Admin-Token；未配置时接口 503 停用——能改 Agent 标准答案的入口绝不默认放行。

🐳 工程化交付

Docker Compose 一键起 PG/Redis；数据库 schema 全程 Alembic 迁移管理，测试用例会在忘跑迁移时报错，防止 create_all 覆盖不齐。

🔒 安全设计亮点

🚫
404 而非 403 —— 防会话枚举

带归属校验的接口，会话不属于当前 token 时返回 404 而不是 403，避免攻击者借此探测哪些会话真实存在。

🔢
删除按手机号列订单的接口

无登录体系下「按手机号列订单」本身就是枚举器——宁可砍功能也不留攻击面，这是接口设计阶段就做出的取舍。

🔑
Admin 接口默认停用

运营后台能改写 Agent 的标准答案，属于高权限面：未配置 ADMIN_TOKEN 时返回 503，明确定义「没配置 = 关闭」。

🚀 快速开始

# 1. 启动基础设施（PostgreSQL + Redis）
docker-compose up -d

# 2. 配置环境变量
cp backend/.env.example backend/.env
# 编辑 .env 填入 LLM_API_KEY 等配置

# 3. 建表并灌演示数据
cd backend && pip install -r requirements.txt
alembic upgrade head
python -m scripts.seed_demo_data   # 可选

# 4. 启动前后端
python run.py               # 后端 http://localhost:8000/docs
cd frontend && npm run dev   # 前端 http://localhost:5173
